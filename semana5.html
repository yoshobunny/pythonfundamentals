La idea más importante

Las reglas de negocio son código

Toda empresa trabaja con reglas del tipo "si pasa esto, entonces hago aquello". A eso se le llama regla de negocio.

1 Una regla escrita en español

Así la escribiría el gerente de ventas en un correo:

📋 Política de descuentos: si el cliente compra más de $10,000 y paga de contado, recibe un 5% de descuento. Si no, paga el precio normal.

2 La misma regla escrita en Python

# Datos del pedido compra = 12000 pago_contado = True # La regla de negocio: más de $10,000 Y pago de contado if compra > 10000 and pago_contado: descuento = compra * 5 / 100 print("Descuento aplicado: $", descuento, sep="") else: print("Precio normal, sin descuento")
Salida en pantalla
Descuento aplicado: $600.0
👀 Fíjate: la regla tiene dos condiciones unidas con "y". En Python esa "y" se escribe and. Eso es justo lo que vamos a ver en la siguiente pestaña.

Antes de empezar

Repaso: toda comparación da True o False

Los operadores lógicos unen respuestas de sí o no. Primero hay que tener esas respuestas.

Cuando comparas con ==, > o <, Python no te da un número ni un texto. Te da True (Verdadero) o False (Falso).

# Le preguntamos al usuario factura = input("¿Tienes la factura? (si/no): ") # Comparamos: ¿lo que escribió es igual a "si"? # La respuesta (True o False) se guarda en tiene_factura tiene_factura = factura == "si" print(tiene_factura)
Salida si escribe si
¿Tienes la factura? (si/no): si True
💡 Léelo así: tiene_factura = factura == "si" significa "guarda en tiene_factura la respuesta a la pregunta ¿escribió si?". Por eso tiene_factura vale True o False, no "si".
⚠️ Escribe si en minúsculas y sin acento. Para Python, "Si", "SI" y "sí" son textos distintos a "si".
Operador 1

and: TODAS se deben cumplir

and significa "y". El resultado es True solo si las dos condiciones son True.

1 En la aduana

Un embarque sale de la aduana solo si trae la factura comercial y ya pagó los impuestos. Si falta cualquiera de las dos, el embarque se queda detenido.

¿Tiene factura?¿Pagó impuestos?tiene_factura and pago¿Qué pasa?
TrueTrueTrue✅ Sale
TrueFalseFalse🛑 Detenido
FalseTrueFalse🛑 Detenido
FalseFalseFalse🛑 Detenido
🧠 Frase para recordar: and es exigente, quiere todo. Basta con un False para que el resultado sea False.

2 En Python

# Datos del embarque tiene_factura = True pago = False # and: las DOS se deben cumplir if tiene_factura and pago: print("✅ Embarque liberado") else: print("🛑 Embarque detenido")
Salida en pantalla
🛑 Embarque detenido

Trae factura (True), pero no pagó (False). Como and exige las dos, el resultado es False y se ejecuta el else.

Operador 2

or: con UNA basta

or significa "o". El resultado es True si al menos una condición es True.

1 En el área de cobranza

La empresa envía el pedido si el cliente paga con carta de crédito o con transferencia anticipada. Con cualquiera de las dos es suficiente.

¿Carta de crédito?¿Transferencia?carta or transferencia¿Qué pasa?
TrueTrueTrue✅ Se envía
TrueFalseTrue✅ Se envía
FalseTrueTrue✅ Se envía
FalseFalseFalse🛑 No se envía
🧠 Frase para recordar: or es flexible, con una se conforma. Solo da False cuando todas son False.

2 En Python

# Formas de pago del cliente carta = False transferencia = True # or: basta con UNA if carta or transferencia: print("✅ Pago aceptado. Se envía el pedido.") else: print("🛑 No hay una forma de pago válida.")
Salida en pantalla
✅ Pago aceptado. Se envía el pedido.
Operador 3

not: le da la vuelta

not significa "no". Convierte True en False y False en True.

1 En el área de cumplimiento

Hay productos que no se pueden exportar sin un permiso especial (por ejemplo, algunos químicos). La regla es: se exporta si el producto NO está restringido.

2 En Python

# El producto NO está en la lista de restringidos restringido = False # not restringido se lee: "si NO está restringido" if not restringido: print("✅ Se puede exportar") else: print("🛑 Necesita permiso especial")
Salida en pantalla
✅ Se puede exportar

Nivel 2

Combinar operadores y la prioridad

En la vida real las reglas mezclan and, or y not en una sola decisión.

1 La regla del semáforo aduanal

📋 Un embarque pasa a revisión física (semáforo rojo) si vale más de $50,000 o si es la primera vez que la empresa importa. Pero si la empresa está certificada como confiable, nunca pasa a revisión.

valor = 60000 es_primera = False es_certificada = True if (valor > 50000 or es_primera) and not es_certificada: print("🔴 ROJO: revisión física") else: print("🟢 VERDE: pasa sin revisión")
Salida en pantalla
🟢 VERDE: pasa sin revisión

2 ¿Cómo lo resuelve Python? Paso a paso

  1. Primero lo que está entre paréntesis: valor > 50000 es True, y True or False da True.
  2. Luego el not: not es_certificada es not True, que da False.
  3. Al final el and: True and False da False. Por eso sale VERDE.

3 El orden en que Python los evalúa

1
Lo que está entre ( paréntesis )
2
not
3
and
4
or

4 ¿Y si quito los paréntesis?

# Mismos datos: valor = 60000, es_primera = False, es_certificada = True if valor > 50000 or es_primera and not es_certificada: print("🔴 ROJO: revisión física") else: print("🟢 VERDE: pasa sin revisión")
Salida en pantalla
🔴 ROJO: revisión física

¡Ahora sale ROJO, aunque la empresa está certificada! Como el and va antes que el or, Python lo leyó así:

valor > 50000 or (es_primera and not es_certificada)

Primero calculó es_primera and not es_certificada, que da False. Luego True or False dio True.

⚠️ Regla de oro: cuando mezcles and con or, usa paréntesis para que Python lea la regla igual que la escribió el gerente.
⚠️ Cuidado

El error más común con or

Este error lo comete casi todo el mundo la primera vez. Si lo entiendes, te vas a ahorrar muchos dolores de cabeza.

1 La regla

📋 El trato preferencial del T-MEC aplica si el país de origen es Canadá o Estados Unidos.

2 Cómo lo hablamos y cómo lo necesita Python

En español decimos "¿el país es Canadá o Estados Unidos?" y nombramos el país una sola vez. Todos entendemos que la segunda parte también habla del país.

Python no adivina. El or parte la condición en dos pedazos, y cada pedazo tiene que ser una pregunta completa que dé True o False:

❓ ¿El país es Canadá? or ❓ ¿El país es Estados Unidos?

3 La forma INCORRECTA

pais = "CHINA" if pais == "CANADA" or "ESTADOS UNIDOS": print("✅ Aplica el T-MEC") else: print("🛑 No aplica el T-MEC")
Salida en pantalla
✅ Aplica el T-MEC

¡China no está en el T-MEC y el programa dice que sí aplica! Veamos los dos pedazos que ve Python:

Pedazo¿Qué es?Resultado
pais == "CANADA"Una pregunta completa: ¿"CHINA" es igual a "CANADA"?False
"ESTADOS UNIDOS"No es una pregunta. Es solo un texto. No compara nada.True (siempre)
False or TrueTrue

4 ¿Por qué un texto solo cuenta como True?

Python tiene una regla: un texto con letras cuenta como True y un texto vacío "" cuenta como False. Puedes comprobarlo así:

print(bool("ESTADOS UNIDOS")) print(bool(""))
Salida en pantalla
True False
📝 Imagínalo como un formulario de aduana con dos casillas: "País = Canadá" y "Estados Unidos". La segunda casilla ya viene palomeada desde la imprenta. Como el or solo necesita una casilla palomeada, cualquier país pasa: China, Japón o el que escribas.

5 La forma CORRECTA

Repite la variable y el == en cada lado del or:

pais = "CHINA" if pais == "CANADA" or pais == "ESTADOS UNIDOS": print("✅ Aplica el T-MEC") else: print("🛑 No aplica el T-MEC")
Salida en pantalla
🛑 No aplica el T-MEC
PedazoPreguntaResultado
pais == "CANADA"¿"CHINA" es igual a "CANADA"?False
pais == "ESTADOS UNIDOS"¿"CHINA" es igual a "ESTADOS UNIDOS"?False
False or FalseFalse
✋ Regla: si a un lado del or o del and no hay una comparación (==, >, <...) ni una variable True/False, está mal escrito.
⚡ Dato interesante

Cortocircuito: Python se detiene en cuanto sabe la respuesta

Python lee las condiciones de izquierda a derecha. Si con la primera ya sabe el resultado, ya no revisa las demás.

1 Con and

Si la primera condición es False, el resultado ya es False sin importar lo demás (and necesita que todas sean True). Python no revisa el resto.

🛃 En la aduana: el agente revisa primero la factura. Si no la traes, ya no revisa los impuestos ni la mercancía. El embarque se queda detenido de una vez.

2 Con or

Si la primera condición es True, el resultado ya es True (or se conforma con una). Python no revisa el resto.

💳 En cobranza: si el cliente ya pagó con carta de crédito, nadie le pregunta si también quiere pagar con transferencia. Ya está pagado.

3 ¿Para qué me sirve? Para evitar errores

La empresa quiere saber si un producto vale más de $100 por pieza. Para eso se divide el valor entre las piezas. Pero si el pedido tiene 0 piezas, dividir entre 0 es un error y el programa se cae.

piezas = 0 valor = 5000 # Primero preguntamos si hay piezas. Si no hay, Python ya no hace la división. if piezas > 0 and valor / piezas > 100: print("Producto de alto valor por pieza") else: print("No se puede calcular o es de bajo valor")
Salida en pantalla
No se puede calcular o es de bajo valor
  1. Python revisa piezas > 0: 0 > 0 es False.
  2. Como es un and y ya hay un False, el resultado ya es False. Se detiene aquí y nunca hace valor / piezas.
  3. Se ejecuta el else. El programa no se cae.

Si escribes las condiciones al revés, Python intenta dividir primero:

if valor / piezas > 100 and piezas > 0:
Salida en pantalla
ZeroDivisionError: division by zero
👉 Regla práctica: pon primero la condición que protege (la que evita el error), y después la que podría fallar.
Diagramas de flujo

¿Cómo se dibuja en el diagrama de flujo?

La condición completa, con sus and, or y not, va dentro de un solo rombo. Sí sale a la izquierda y No a la derecha.

💡 Un solo rombo, porque es una sola decisión: ¿sale o no sale el embarque? El and se escribe dentro del rombo igual que en el código.
